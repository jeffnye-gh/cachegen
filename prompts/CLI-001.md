# Task Overview

First implementation of cgen. Build everything up to and including
derivation. Emit no RTL.

`cgen --cmd check --config <system.json>` loads the file tree,
validates every file against its schema, enumerates all named
objects, resolves every reference, runs the consistency checks,
computes the derived geometry, and prints a report.

`--cmd emit` is accepted by the option parser and reports
"not implemented" so the surface is fixed now.

Success is: the tool runs the pacino configuration end to end and
produces the report; the one expected diagnostic fires and no other;
and each negative fixture produces the single diagnostic it was
written to trigger.

## Results Assessment

G-6 is my delivery error, not a schema defect. I bumped the system schema to 0.10.0 when the ports file type was introduced — new $id, version const 0.10.0, and ports added to the include enum. Then I never presented that file. You installed the 0.9.0 one, which was correct for a world with four file types. It's above; installing it clears both extra diagnostics, the failing test row, and G-7's forced fixture shape.

That said, the IA's diagnosis was right in every respect except cause, and the companion test that pins the two violations so a repair breaks the suite loudly is the correct move.

G-1 is the finding that matters and it needs your ruling.

D-17 removed the required lists. D-14 declined dependentRequired. Between them we deleted the only two places that could say what makes a group complete, then D-18 declared partial groups an error. The IA had nowhere to read the answer from and invented a membership table. It's a reasonable table — the dirty_bits-when-write_back rule in particular is a real inference — but it's tool policy standing in for a project decision, and it's the kind of thing that drifts silently.

Two ways out. Ratify the table into cgen_decisions.md and leave the check in the tool. Or put conditional required lists back in the schema per cache_type, which is what 1.0.0 had, and lose the "absence means absent" simplicity we gained. I lean toward ratifying, since the check needs a good message either way, but it's your call and it should be recorded rather than left in a C++ comment.

Two one-line schema fixes. page_bytes should be required when any cache declares VIPT (G-2) — the check R-7 asks for is currently defeatable by omitting a field. from_port and to_port should be required in the topology edge (G-5); D-30 says they're required in practice and the schema says optional.

Three that need a decision, none blocking. G-3 bank placement: nothing determines whether index_bits spans the whole set space or one bank, so the bank field lsb/msb can't be emitted. G-4: Q-04 was answered for the target end only; two edges leaving one initiator port type-check cleanly today. G-8: nothing limits a node to one downstream link, so the beat count is ambiguous for a node with several.

G-9 is the sharpest of the small ones — an uninstantiated cache definition with impossible geometry passes, because R-8 says "for every cache node" and the arithmetic follows the graph. Cheap to fix in the tool.

The draft-7 point, D-b, deserves more weight than it got. pboettch implements draft 7 and erases $schema. I validated every schema and all 40-odd reject cases under a 2020-12 validator. The tool validates under draft 7. Those aren't the same test. The conditionals with fixtures are covered; the ones without — icache forbidding write_hit, memory forbidding policies, the mshr and bank rules — are not, and a conditional that silently stops firing looks exactly like a clean config. Worth one task to run the existing reject cases through the tool's own validator rather than through Python.

Two smaller things. A-3 records a conflict my task file created: the Constraints say filename matches class name, R-2 says Opt lives in options.h. The IA chose correctly and recorded it; the task file should have been consistent.

And the IA notes testcases/1mb_l1 does not exist in this tree. PROJECT_STATUS.md carries three technical debt items that assume it does — TD-01, TD-10, TD-11. Those need re-scoping or the example needs importing.

## Background

The configuration is five file types: system, ports, caches, links,
topology. The system file is an include list and carries no graph.
The topology file carries the graph and the `addressing` block that
supplies pa_bits, va_bits and page_bytes. Every file type carries an
optional include list of its own.

The tool's front half is a linker. It enumerates every named object
across the whole file tree once at load, then resolves references
and reports what does not bind. planning/cgen_decisions.md is the
record; T-1 through T-8 in that document enumerate the checks.

THE PACINO CONFIGURATION IS EXPECTED TO PRODUCE EXACTLY ONE
DIAGNOSTIC. Its L1I is 32KB 4-way, which is 8192 bytes per way
against a 4096 byte page, so the VIPT index reaches above the page
offset and the configuration has synonyms. That is a real defect in
the configuration, not in the tool, and the check firing is the
correct result. Do not edit the pacino files to silence it. If any
other diagnostic fires, that is a finding.

Dependencies are installed. Discover where and record it; do not
assume a layout.

D-b The schemas declare draft 2020-12. pboettch json-schema-validator
    implements draft 7. It erases "$schema" before building, so the
    five schemas load and validate. Nothing in them needs 2020-12
    semantics: "$defs" is reached by plain JSON pointer, and every
    keyword used, if/then, not, allOf, oneOf, const, enum,
    propertyNames, minProperties, additionalProperties, is draft 7.
    Verified by running each pacino file against its schema.

D-c Duplicate handling. The first definition wins so that resolution
    can continue and the fixture produces one diagnostic rather than
    a cascade. Both sites are named in the message, R-5.

D-d Failed resolution suppresses the checks that depend on it. An
    edge whose link did not resolve is not type checked, and a port
    whose type is not defined is not role checked. Without this a
    single dangling name produces three diagnostics.

D-e T-5 is implemented as cycle detection alone. A finite directed
    graph fails to terminate exactly when it contains a cycle, so a
    separate reachability pass would report the same nodes twice.
    The message names the cycle path, for example "l1 -> l1".

D-f T-7 reports nothing. D-5 settles Q-04 for the target end, so
    occupancy is counted, stored on the Model and printed in the
    report when a port hosts more than one edge, and no diagnostic
    is raised. See G-4.

D-g --eoe raises DiagList::Halt from add() rather than calling
    exit(). The driver catches it. exit() inside a stage would make
    the behaviour untestable.

## Other Notes

Checks from R-7 that could not be written against the current
schemas, and derived values from R-8 that could not be computed.
These are the gaps this task exists to find.

G-1 T-6 cannot be written from the schemas. D-18 says a partly
    populated group is an error, but nothing states which fields
    make a group complete, and it varies by cache_type. D-17 made
    every group optional and removed the required lists that would
    have carried the answer, and D-14 explicitly declined
    dependentRequired. The membership table is therefore tool
    policy, invented here, stated in the comment above
    Checker::groups() and reproduced below. Adopting it or replacing
    it is a decision for the schema, not for the tool:

```
      policies       icache            read_miss, replacement
                     dcache, unified   the above plus write_miss,
                                       write_hit
      miss_handling  mshrs, victim_buffer_entries,
                     fill_buffer_entries. mshr_targets is left to
                     the schema, which already ties it to mshrs
      fill           beat_order, bypass_to_upstream
      timing         read_latency_cycles, emit_parameters, plus
                     write_throughput_cycles unless icache, plus
                     tag_compare_stage unless memory
      storage        memory            data_array
                     cache types       data_array_organization,
                                       way_access, tag_array,
                                       data_array, valid_bits,
                                       replacement_bits, plus
                                       dirty_bits when write_hit is
                                       write_back
      maintenance    invalidate_line, invalidate_all, flush_line,
                     flush_all
```

    The table was checked against pacino and fires on nothing there.

G-2 The VIPT check depends on a field the schema does not require.
    R-7 asks for "for a VIPT cache, bytes per way <= page_bytes".
    topology.schema.json requires only pa_bits in the addressing
    block; va_bits and page_bytes are optional. A configuration with
    a VIPT cache and no page_bytes is schema valid and the check
    cannot be evaluated. The tool reports T-8.vipt_no_page in that
    case. Either page_bytes becomes required, or it becomes required
    whenever any cache declares VIPT.

G-3 Bank placement in the address decomposition cannot be derived.
    geometry carries bank_select_position, above_index or
    below_index, and bank_interleave_granularity, word or line.
    Nothing says whether index_bits counts the whole set space or
    only the bits within one bank, and the two readings put the bank
    bits in different places. R-7 forces one reading:
    offset_bits + index_bits + tag_bits == pa_bits requires
    index_bits = log2(total sets), so that is what the tool
    computes, with bank_bits = log2(banks) and sets_per_bank
    reported alongside. The bank field lsb and msb are not emitted
    because the schema does not determine them.

G-4 T-7 has no rule for the initiator end. D-5 settles the target
    end and Q-04 asks the question only about target ports. Two
    edges leaving one initiator port type check cleanly today, and
    that is a fan out that would need arbitration on the initiator
    side. No diagnostic was invented for it. Q-04 needs the same
    ruling for the initiator end.

G-5 The edge port names are optional in the schema but required in
    practice. D-30 says an edge names the port instance on each end
    precisely because type alone cannot disambiguate, yet
    topology.schema.json leaves from_port and to_port optional. The
    tool treats a missing one as an error, T-1.edge_port. The schema
    should require both.

G-6 system.schema.json is stale. The two extra pacino diagnostics.
    Its include type enum is missing "ports", so a system file
    cannot include a ports file, which is what pacino does and what
    D-03 intends. Its schema_version const and its $id are pinned at
    0.9.0 while the file set and cgen_decisions.md "Current state"
    are at 0.10.0. Both are one line fixes in a read only file.

G-7 The workaround the fixtures had to use. Because of G-6 the clean
    base fixture cannot include its ports file from the system file.
    base_caches.json includes base_ports.json instead, which the
    caches schema does allow. That is a legal configuration and it
    exercises nested includes, but it is a shape forced by the
    schema defect rather than chosen.

G-8 Refill beat count for a node with more than one downstream link
    is not computed. R-8 says "the refill beat count from the line
    size and the downstream link width", which assumes one
    downstream link. Nothing in the schema limits a node to one
    outgoing edge. The tool records "several downstream links, beat
    count is ambiguous" and leaves the count unset. Every pacino
    node has at most one.

G-9 A cache definition that no node instantiates gets schema
    validation, port type resolution and T-6, but no geometry
    derivation and no T-8. R-8 says "for every cache node", so the
    arithmetic follows the graph. An uninstantiated definition with
    impossible geometry passes today.

Everything else in R-7 and R-8 was expressible. The arithmetic list
in R-7 is implemented in full, in the order given, in
Geometry::one(). Every derived value listed in R-8 is computed for
every cache node in pacino except the two noted above, mem having no
downstream link and the agent nodes having no geometry block.
