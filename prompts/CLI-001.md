# Task Overview

First implementation of cgen. Build everything up to and including
derivation. Emit no RTL.

`cgen --cmd check --config <system.json>` must load the file tree,
validate every file against its schema, enumerate all named objects,
resolve every reference, run the consistency checks, compute the
derived geometry, and print a report.

`--cmd emit` is accepted by the option parser and reports
"not implemented" so the surface is fixed now. RTL generation is a
later task.

Success is: the pacino configuration passes clean, and each negative
fixture produces the one diagnostic it was written to trigger.

## Hypothesis

The five schemas and the pacino configuration are complete enough to
drive a tool. This task tests that by building the front half of the
tool and running it against them.

A gap in the schema shows up here as a check that cannot be written
or a derived value that cannot be computed. Report either rather
than working around it.

## Background

The configuration is five file types: system, ports, caches, links,
topology. The system file is an include list and carries no graph.
Every file type carries an optional include list of its own.

The tool's front half is a linker. It enumerates every named object
across the whole file tree once at load, then resolves references and
reports what does not bind. planning/cgen_decisions.md is the record;
T-1 through T-8 in that document enumerate the checks.

## Binding Previous Decisions

1. LIBRARIES ARE FIXED. nlohmann/json for parsing. pboettch
   json-schema-validator for schema validation. Boost.ProgramOptions

## Specific Requirements

R0 -- IDIOMS FIRST. Read tools/jnutils/idioms,
      tools/jnutils/program_options and tools/jnutils/msg before
      writing code. main and the options class follow those
      patterns.

R1 -- OPTIONS. Class `Opt` in cli/inc/options.h and
      cli/src/options.cpp, Boost.ProgramOptions. No positional
      arguments.

```
  --cmd={check,emit}   required
  --config=<path>      required, path to the system file
  --output=<dir>       default ./output
  --eoe                exit on first error, default off
  --help
  --version
```

      --cmd emit parses and reports not implemented.

R2 -- LOADER. Read the system file, follow every include, read each
      included file. Detect include cycles and report the cycle
      path. Record for every loaded file its path and its declared
      file_type, and verify the declared type matches the type the
      include entry claimed.

R3 -- VALIDATION. Validate every loaded file against the schema for
      its file_type. Schema files are read from disk, not compiled
      in. Their directory is derived from the tool location or given
      by an option of your choosing; state which in Results Capture.

R4 -- SYMBOL TABLE. Enumerate every named object across all files:
      port types, cache definitions, link definitions, topology
      nodes. Detect duplicate definitions and report both sites.
      This is T-2.

R5 -- RESOLUTION. Bind every reference: node to cache definition,
      edge endpoints to nodes, edge link to link definition, cache
      port to port type, link end port type to port type. Every
      unresolved name is a diagnostic naming the referencing site.
      This is T-1.

R6 -- CHECKS. Implement T-3 through T-8 from cgen_decisions.md:
      port type compatibility on both ends of every edge; port role
      against edge direction; graph terminates and has no cycles;
      field group completeness; and the geometry arithmetic. For the
      arithmetic, at minimum: capacity divides line times
      associativity to an integer set count, set count is a power of
      two, the address fields sum to pa_bits, and for a VIPT cache
      bytes per way against page size.

      T-7, port occupancy, is decided: a target port may host more
      than one edge. Do not report that as an error.

      pa_bits and page_bytes have no home in the current schemas.
      Report how you handled the address checks without them.

R7 -- DERIVATION. For every cache node compute sets, offset bits,
      index bits, tag bits, each field's lsb, msb, mask and shift,
      bytes per way, and the refill beat count from the line size
      and the downstream link width. Derived values are computed,
      never read from the input.

R8 -- REPORT. --cmd check prints the node list with its derived
      geometry, the edge list with resolved link types, and every
      diagnostic. Exit non zero if any diagnostic is an error.

R9 -- DIAGNOSTICS ARE AN OBJECT, not a string thrown from the point
      of failure. A diagnostic carries at least the file, a path
      into the document, a severity, and a message. Stages
      accumulate diagnostics and report them together unless --eoe
      is set. The reason the checks are in the tool rather than in
      the schema is the quality of these messages; a diagnostic that
      does not say which file and which object is not adequate.

R10 -- TESTS. gtest under cli/tb. One positive fixture, the pacino
      configuration. Negative fixtures, one per diagnostic, each
      minimal and each triggering exactly one:

```
  dangling edge endpoint
  dangling cache reference
  dangling link reference
  unknown port type
  duplicate definition across two files
  port type mismatch on an edge
  port role mismatch against edge direction
  include cycle
  include type mismatch
  partly populated field group
  graph does not terminate
  schema violation
```

R11 -- BUILD. A Makefile that builds cgen and the tests. No CMake.
      State how the three third party dependencies are obtained.
