associativity 4 -> 8. One field, no other change.

```
  was   32768 / 4 ways = 8192 bytes per way   index [12:6]  128 sets
  now   32768 / 8 ways = 4096 bytes per way   index [11:6]   64 sets
```

VIPT indexes with the virtual address and compares tags against the
physical address, which is only sound while every index bit sits below
the page offset, because those bits are not translated and VA equals PA
for them by construction. At 8192 bytes per way the index reached bit
12, which is translated, so two virtual addresses mapping to one
physical line could differ in that bit and the line could land in two
different sets. That is the synonym: two copies of one line, and an
invalidate arriving by physical address not knowing which set holds it.

The constraint is a cap on the way, not on the cache, since capacity
over ways is what sets the index span. A way must not exceed a page, so
at a 4096 byte page a way caps at 4096 bytes and 32KB needs eight of
them. 16KB four-way also passes and throws away half the cache. PIPT on
the I side removes the constraint entirely at the cost of waiting on
translation before the index, which is a fetch pipeline decision and
was not taken. Eight ways is the option that keeps the 32KB, and it
makes l1i and l1d the same geometry, so both L1s can come out of one
parameterized module with different policy fields. handoff 001 section
6 had already derived this and the example contradicted it, so this
restores a solve rather than making one.
