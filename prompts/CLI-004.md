# Task Overview

RTL emission. cgen --cmd=emit reads the pacino configuration and
writes the complete SystemVerilog design, its testbenches and a
Make build environment to ./output.

The bar is mechanical and it is the whole bar: every emitted file
lints clean under Verilator and the generated build compiles and
elaborates without error. Simulation is not required to pass. A
testbench that elaborates and runs is enough for this task.

Nothing is deferred for want of a decision. Where a decision is
open, the emitter makes one, applies it consistently, and reports
it under R-9. A reported convention is a deliverable. A guessed one
that is not reported is a defect.

The C++ functional model is NOT in this task. It is CLI-005.

Part of this work may already be present in the tree. Read before
writing. See R-1.

## Background

The front half is complete and clean. cgen --cmd=check on
testcases/pacino produces no diagnostics. geometry derives sets,
the offset, index and tag fields, capacity, line, associativity and
the bank divide, and the VIPT index budget is met on both L1s.

pacino is six nodes:

```
  ifu, lsu   agents, not synthesizable, needed as TB drivers
  l1i        icache 32KB 8-way 64B VIPT, one bank
  l1d        dcache 32KB 8-way 64B VIPT, one bank
  l2         unified 512KB 8-way 64B PIPT, TWO BANKS
  mem        memory 1GB, behavioural model, not synthesizable
```

Edges are TileLink. l2 keeps three interfaces, up_i, up_d and down,
so the I side and the D side hold their own link and their own
conformance level.

Two rules shape the emitter and are not re-argued. D-39: generated,
not transcribed. The PLRU update and victim tables and the address
field decomposition are built once and emitted to every consumer,
not written four times and checked for agreement. And from handoff
001: an emitter bug is one bug per output file, which is why R-8
tests the whole build rather than sampling it.

### R-6, the bank field

**The two together DO determine the field.** Q-09 is answered by
the emitter, not deferred, and the answer is corroborated.

The derivation, stated as the reasoning rather than as a result:

```
  1  offset + index + tag == pa_bits leaves NO BITS OVER. The tool
     already computes the index as spanning the whole set space
     because that rule forces it. There is therefore no room for
     a fourth field beside the three.

  2  So a bank select is a SUBFIELD of one of the three. It cannot
     be a field of its own.

  3  bank_interleave_granularity says WHICH of the three. line
     means the select sits at or above the line boundary, which
     puts it in the index. word means it sits below the line
     boundary, which puts it inside the offset.

  4  bank_select_position says WHICH END of the index. above_index
     takes the top bank_bits, below_index takes the bottom
     bank_bits, the ones next to the offset.
```

That reading makes the two fields orthogonal rather than
contradictory, which is what makes it the right one. A reading in
which both fields describe position would have them disagree for
l2, which declares line and above_index: line interleaving in the
usual sense means consecutive lines alternate banks, which is the
bit just above the offset, and that is below_index. Read as
granularity and position they do not conflict at all.

Applied to l2, and this is the answer R-6 asks for:

```
  l2, 512 KB, 8 ways, 64 B lines, 2 banks, line, above_index

  offset    [5:0]     6 bits
  index     [15:6]   10 bits    the whole set space, 1024 sets
  tag       [31:16]  16 bits

  bank      [15:15]   1 bit     the TOP 1 bit of the index
  set index [14:6]    9 bits    what is left of the index
```

And for mem, which has 8 banks and the same declarations:

```
  mem, 1 GB, 1 way, 64 B lines, 8 banks, line, above_index

  offset    [5:0]     6 bits
  index     [29:6]   24 bits
  tag       [31:30]   2 bits

  bank      [29:27]   3 bits
  set index [26:6]   21 bits
```

**The corroboration.** This is the part that makes it an answer
rather than a guess. sets_per_bank is derived independently, by
dividing the set count by the bank count, and it was derived before
this task existed. The set index the field arithmetic leaves is
derived from the field bounds. They are two routes to one number
and geometry.cpp asserts they agree:

```
  l2    field arithmetic leaves 9 bits    2**9  = 512
        sets_per_bank = 1024 / 2         = 512     agree
  mem   field arithmetic leaves 21 bits   2**21 = 2097152
        sets_per_bank = 16777216 / 8     = 2097152 agree
```

If they had disagreed, geometry sets bank_resolved false, keeps the
note, and emits the field NAMED and its bounds UNRESOLVED, which is
what R-6 asks for in that case. That path is live and reachable:
bank_interleave_granularity word takes it, and the note it leaves
says why. See Deferred Work.

The report shows it:

```
  -I: cgen:   node 'l2' cache 'l2' type unified indexing PIPT
  -I: cgen:     bits offset 6  index 10  tag 16  bank 1
  -I: cgen:     bank   [15:15] bits 1 shift 15 mask 0x00008000
  -I: cgen:     setidx [14:6] bits 9 shift 6 mask 0x00007fc0
  -I: cgen:       the index spans the whole set space, so the
                  above_index select is taken out of it, leaving
                  512 sets in each of the 2 banks
```

The derivation is in cli/src/geometry.cpp, Geometry::bank_field,
with Model::Geom gaining bank, set_index, bank_granularity,
bank_position, bank_resolved and bank_note. The Constraints said
not to change geometry's derivations and to add a value there if
the emitter needs one geometry does not produce. Nothing existing
was changed. The bank field is new, computed after the existing
arithmetic, and no existing value moved.

### R-7, the offset unit

**Byte based.** The offset field is a byte offset within the line.
Every node's package says so at the top of its addressing block.

The one named parameter is **AddrUnitBytes**, in
`output/<node>/rtl/<node>_pkg.sv`. It carries the node name prefix
in the emitted text, so the four caches carry L1iAddrUnitBytes,
L1dAddrUnitBytes, L2AddrUnitBytes and MemAddrUnitBytes. Every word
count and word index in the tree derives from it and from nothing
else.

As emitted, in l1i_pkg.sv:

```systemverilog
  // R-7. THE OFFSET UNIT IS THE BYTE. The offset field of an
  // address is a byte offset within the line.
  //
  // L1iAddrUnitBytes is the size of ONE ADDRESS UNIT in bytes.
  // It is 1, which is byte addressing. Every word count and
  // every word index below derives from it and from nothing
  // else, so reversing this design to word based addressing
  // is one edit, on the L1iAddrUnitBytes line, in this one file.
  localparam int unsigned L1iAddrUnitBytes = 1;

  localparam int unsigned L1iWordBytes     = 4;
  localparam int unsigned L1iWordBits      = L1iWordBytes * 8;
  localparam int unsigned L1iWordsPerLine  = L1iLineBytes /
                                             L1iWordBytes;
  localparam int unsigned L1iWordIdxBits   = $clog2(L1iWordsPerLine);
  localparam int unsigned L1iWordIdxLsb =
      $clog2(L1iWordBytes / L1iAddrUnitBytes);
  localparam int unsigned L1iWordIdxMsb   = L1iWordIdxLsb +
                                            L1iWordIdxBits - 1;
```

The reversal is one edit in one file, as R-7 requires.
L1iAddrUnitBytes = 4 makes WordIdxLsb 0, which moves the word index
from bits [5:2] to bits [3:0] and turns the address into a word
address. Nothing else changes, because word_of is the only thing
that reads it and every consumer calls word_of.

```
  1. IMPORTSTAR                      35 sites, every module file

     What      a wildcard import reaching $unit scope
     Why       verilog_style.md REQUIRES the import at file scope
               and before the module declaration, and explicitly
               rejects the module header form that would have
               scoped it. The style rule wins on emitted text per
               the Context Comments, so the warning is waived and
               the difference is reported. See Deferred Work,
               finding 1, because this one is not only a warning.
     Suppressed /* verilator lint_off IMPORTSTAR */ around the
               import lines and nothing else, three lines wide.

  2. UNUSEDPARAM                     11 sites, every package file

     What      a package localparam nothing consumes
     Why       a generated package STATES the configuration and the
               protocol. cgen_tl_pkg carries the whole TileLink
               1.9.3 opcode space so a consumer decoding a channel
               has every name; a node package carries the whole
               derived geometry. One module consumes a subset. The
               constants are the artifact, not dead code, and
               emitting only the consumed ones would make the
               package a function of its consumers.
     Suppressed one lint_off / lint_on pair spanning the package
               body. It cannot leak, a package is the file.

  3. UNUSEDSIGNAL                    22 sites

     What      a signal read nowhere, or read only in part
     Why       three distinct causes, all inherent to generated
               code:

                  signalling for a declared conformance level the
                  design does not exercise and tie it off. B, C and
                  E are exactly that. The outputs are driven to
                  zero and the inputs are collected into one
                  unused_bce sink so they are not floating and not
                  silently ignored.

               b) protocol fields a given adapter does not consume,
                  11 sites. a_param and a_corrupt on every slave, D
                  channel opcode, param, size, source and sink on a
                  whole line master. They are on the link because
                  the link declares them; this end has no use for
                  them.

               c) a bundle wire the node does not use, 6 sites. An
                  icache carries rw, wdata and wstrb on its core
                  port because the LINK declares them, and never
                  reads them. Omitting them from the port list
                  would make the two ends of one link different
                  shapes, which is worse.

     Suppressed a named sink wire, unused_a / unused_bce /
               unused_err / unused_wr / unused_tb / unused_ev, with
               lint_off / lint_on around the declaration alone. The
               sink is a reduction OR, so the signals are read and
               the result goes nowhere.

  4. BLKSEQ                          6 sites

     What      a blocking assignment inside always_ff
     Why       NOT A PREFERENCE, a language rule. The sparse store
               in the memory model and in the two testbench
               responders is an associative array, and IEEE
               1800-2023 6.21 FORBIDS a nonblocking assignment to a
               dynamically sized variable. Verilator enforces it as
               an error. The store cannot be a declared array: mem
               is 1 GB. So the write is blocking and BLKSEQ is off
               across that process. Every other assignment in those
               processes is nonblocking.
     Suppressed lint_off / lint_on around the one always_ff that
               touches the store.
```

```systemverilog
//

//   valid  flop_file, combinational, cleared on reset
//   repl   flop_file, combinational
//

//

// synthesizable reset clear loop of D-40. It is emitted as
// the configuration asks and is correct for a flop file.
//--------------------------------------------------------------------

// the project verilog style asks for. Verilator's IMPORTSTAR objects
// to a wildcard in $unit scope, so it is turned off across these
// lines and nowhere else.

/* verilator lint_on IMPORTSTAR */

  input  logic  rstn,

  // read port, one set, every way
  input  l1i_set_t  rd_set,
  output l1i_tag_t  rd_tag   [L1iWays],
  output logic  rd_valid [L1iWays],
  output l1i_repl_state_t rd_repl,

  // allocate one way of one set
  input  logic  wr_en,
  input  l1i_set_t  wr_set,
  input  l1i_way_t  wr_way,
  input  l1i_tag_t  wr_tag,
  input  logic  wr_valid,

  // replacement state write back
  input  logic  rp_en,
  input  l1i_set_t  rp_set,
  input  l1i_repl_state_t rp_val,

  input  logic  inv_en,
  input  l1i_set_t  inv_set
);

      for(int unsigned w = 0; w < L1iWays; w++) begin
        for(int unsigned s = 0; s < L1iSetsPerBank; s++) begin

      rd_valid[w] <= val_mem[w][rd_set];
    end
```

### R-9, the generator conventions the emitter decided

D-40's file does not exist. Every convention below was decided
here, applied consistently, and is reported rather than written
into any planning file. For each: the choice, the alternatives, and
whether anything already in the tree implied an answer.

**1. Module and file naming, and their relationship**

Chosen: one module per file, the file named exactly
`<module>.sv`. Every module name is `<instance>_<role>`, built from
the topology INSTANCE name.

```
  <n>_pkg          the package
  <n>_<iface>_slv  the slave end of one interface
  <n>_<iface>_mst  the master end of one interface
  <n>_meta_array   tag, valid, dirty, replacement state
  <n>_data_array   line storage
  <n>_ctrl         the control of one bank
  <n>_bank         one bank
  <n>              the node
```

Alternatives: the DEFINITION name rather than the instance name,
and a shared module set parameterised per instance. Both rejected
by R-4, which requires the instance name for the directory; using
the definition name for the module would then put two differently
named things in one directory the moment a definition is
instantiated twice.

Implied by the tree: yes, partly. Verilator's DECLFILENAME wants
the file to match the module, and D-48's one class per file is the
same instinct one level up.

Worth stating: the array module is called **meta_array**, not
tag_array. It holds the tag, the valid bit, the dirty bit and the
replacement state, all addressed by the same set index in the same
cycle. Calling it a tag array would name a quarter of its contents.

**2. Parameter naming, and package constants versus module
parameters**

Chosen: **everything is a package localparam. No module has a
parameter.** Constants are CamelCase, types and functions are
snake_case with a _t or an _of.

The reason is D-37. A module parameter is a value someone can
override at instantiation, and every one of these values was
DERIVED by the tool from the configuration. An overridable
derived value is a second source that can disagree with the first,
which is the S-12 class of defect. Emitting them as package
localparams makes them un-overridable by construction.

The one exception is HalfPeriod on a testbench, which is a
`parameter` precisely so it CAN be overridden with -G at build
time. It is simulation control, D-41, and it is on a testbench and
not on the design.

Alternative: module parameters with defaults, the conventional RTL
idiom. Rejected on D-37 as above.

**3. Signal and port naming beyond clk and rstn**

Chosen: `<interface>_<signal>` for everything on a link, where
`<signal>` is the bundle's own local name. For TileLink that gives
`<iface>_<channel>_<field>`: `up_i_a_valid`, `mem_d_data`. For the
ad hoc port it gives `core_valid`, `core_wstrb`.

The internal bundle behind an adapter is `req_*` / `rsp_*` toward
the core side and `mreq_*` / `mrsp_*` toward memory, and it is the
SAME SHAPE on every node, so a control never knows which protocol
its request arrived on.

Implied by the tree: the interface name is D-42's, so
`<interface>_` was already the natural prefix. Nothing implied the
channel level.

The bundle is derived once, in cli/src/link_sig.cpp, from the
master's point of view, and the slave end is the same list with
every direction reversed. That is D-39 applied to port lists: the
two ends of an edge cannot drift apart because there is one list.

**4. The tree PLRU bit encoding, and the invalid way tie break**

Chosen, and stated at its one implementation in
cli/src/replacement.cpp:

```
  The state of a set is ways-1 bits, one per interior node of a
  binary tree whose leaves are the ways. Node 1 is the root and
  node k has children 2k and 2k+1, so node k's bit is state[k-1].

  A NODE BIT IS THE DIRECTION TO THE VICTIM. 0 points at the left
  subtree, 1 at the right. Finding a victim is a walk from the
  root following the bits. Touching a way is the same walk with
  every bit on the path set to point AWAY from that way.

  The reset state is all zeros, so way 0 is the first victim of
  every set.
```

Alternative encodings: the bit as "the side just used" rather than
"the side to evict", and a level major rather than heap layout.
Both work. D-40 says so directly: any encoding works provided one
generator emits all consumers from it. What matters is that there
is one, and there is.

Emitted as TABLES, which is what D-39 names. For 8 ways that is a
128 entry victim table and a 128 by 8 update table, both filled by
running the walk in the tool, so the encoding above is written down
exactly once. Above 256 states the tables would stop being a
readable artifact and the same walk is emitted as the walk itself,
one generated line per tree level. pacino is 8 ways everywhere so
the table form is what actually ships.

**The invalid way tie break: the LOWEST NUMBERED INVALID WAY wins,
and an invalid way always beats the replacement victim.** Nothing
in the tree implied a direction. The reason for down rather than up
is that it makes a cold set fill from way 0 upward, which is a fill
order a testbench can predict; the l1i and l1d tests assert exactly
that by filling all 8 ways of one set and requiring every one to
hit afterwards.

**5. The replacement reset state across policies**

Chosen: **out of reset, every policy makes way 0 the victim.**

Tree PLRU gets this free from an all zero state. True LRU did not:
the obvious reset, rank i for way i, makes the HIGHEST numbered way
the first victim. That was found by a test rather than by
inspection, and the reset was changed to rank ways-1-i so a cold
set fills from way 0 upward under either policy.

The alternative is to let each policy have its natural reset. It
was rejected because a cold cache would then fill differently
depending on which policy the configuration named, and a testbench
cannot predict a fill order that moves with the policy.

**6. The non synthesizable reset clear loop**

Chosen: **the configuration decides, per array, and the emitter
emits the mechanism that matches.**

```
  cleared_on_reset true    a for loop over every way and set in
                           the reset branch of always_ff. NOT
                           SYNTHESIZABLE for a memory macro and
                           correct for a flop file, which is what
                           the l1s declare their valid bits to be.
                           This is D-40's reset clear loop and it
                           is emitted as asked.

  cleared_on_reset false   a POST RESET WALK. The control starts
                           in C_INIT, walks the set index clearing
                           valid through the array's inv_en port,
                           and holds req_ready low until it is
                           done. Synthesizable. l2 declares its
                           valid bits in SRAM and not cleared, so
                           l2 gets this.
```

Alternative: always emit the loop and let synthesis complain. It
was rejected because the configuration already distinguishes the
two cases and the whole point of a generator is to act on that.

Two things this settles that nothing in the configuration says.
The four metadata sub arrays each declare their OWN read port, and
a control can only have one read latency. **The module presents the
SLOWEST: if any sub array is registered, every read is registered.**
l1i declares a registered tag array and combinational valid bits,
so its valid read is registered on the way out to match. This is
stated in the emitted file's header rather than left to be
rediscovered.

**7. How a generated file names the configuration it came from**

Chosen: the header names the SYSTEM NAME and the BASE NAME of the
configuration file, and never the path.

```
  // SPDX-License-Identifier: Apache-2.0
  // Copyright (c) 2026 Jeff Nye, uarchlabs.com
  // SPDX-FileCopyrightText: 2026 Jeff Nye <jeff@uarchlabs.com>
  //-----------------------------------------------------------
  // FILE:      l1i_pkg.sv
  // GENERATED  This file is generated by cgen. DO NOT HAND
  //            EDIT. Every edit is lost the next time the
  //            configuration is emitted. Change the
  //            configuration and emit again.
  // TOOL:      cgen 0.1.0
  // SOURCE:    system 'pacino', from pacino_system.json
  //-----------------------------------------------------------
```

The path is deliberately absent. R-11 forbids an absolute path in
an emitted file and --config accepts one, so echoing what the user
typed would break determinism on the user's spelling of the path.
The base name and the system name are both properties of the
configuration and neither moves.

Alternative: a relative path from the output directory. Rejected,
it depends on where --output points.

**8. The TileLink signal naming and channel bundling**

Chosen: **flat signals, one per field, named
`<iface>_<channel>_<field>`.** No struct, no interface, no
modport.

```
  A  opcode param size source address mask data corrupt
  B  opcode param size source address mask data corrupt     TL-C
  C  opcode param size source address data corrupt          TL-C
  D  opcode param size source sink denied data corrupt
  E  sink                                                   TL-C
```

plus valid and ready on each. A field whose per link parameter is
zero is not emitted at all, because a zero width signal is illegal;
that is why source_bits 0 would drop a_source rather than emit
`logic [-1:0]`.

Alternatives: a packed struct per channel, or a SystemVerilog
`interface` with modports. The struct is tidier to read and makes
the two ends' widths one declaration. Both were rejected for the
same reason: they are harder for Verilator to lint cleanly at the
boundary, and an `interface` is not universally synthesizable. Flat
signals are what every TileLink implementation in the wild emits at
a module boundary.

Conformance is honoured, not flattened. TL-UL and TL-UH carry A and
D; TL-C additionally carries B, C and E. pacino's l1d to l2 link
declares TL-C and this design has no probe path and no release
path, so B, C and E ARE EMITTED AND TIED OFF, per R-5. What was
tied off:

```
  channel B   the slave's probe path
  channel C   the master's probe response and release path
  channel E   the master's grant acknowledge
```

Also tied off, on the ad hoc port: nothing. pe_port declares
write_response false, so a write has no response and completes when
it is accepted, and the testbench task knows that because the
BUNDLE says so, not because it was told.

**9. The memory model's timing behaviour**

Chosen:

```
  storage    an ASSOCIATIVE ARRAY keyed by beat address. mem is
             1 GB and that is not a declarable array. Only the
             beats a test touches ever exist.
  latency    read_latency_cycles from the configuration, counted
             down in a wait state. It is a property of the memory,
             not simulation control, so it belongs in the model
             and not on a command line. D-41.
  throughput one request at a time. write_throughput_cycles is
             carried in the package and NOT consumed. Reported.
  beats      derived from the request's size field and the link
             width, never configured.
  range      range_check true answers an address at or above the
             capacity with denied rather than wrapping it.
  init       format none, so the store starts empty and an
             unwritten beat reads as zero.
```

Alternative: a fixed small backing array with an address mask.
Rejected, it would make a range_check test meaningless.

The two testbench responders are the same shape but return a SEED
for an unwritten beat rather than zero, so a unit test can predict
what a fill should contain without keeping its own model.

**10. Arbitration, which the configuration has no field for**

This one is a finding as much as a convention, and it is in
Deferred Work as finding 2.

Chosen: **round robin, everywhere the emitter had to arbitrate**,
with a pointer per contended resource advanced on every grant.

Two places need it and D-27 covers neither:

```
  a) l2's up_i and up_d competing for the banks. D-27 puts
     arbitration on an INTERFACE, and each of these carries one
     port, so no interface has anything to arbitrate. What
     contends is one interface against another.
  b) l2's two banks competing for the single downstream link.
```

Alternative: fixed priority, lowest interface first. Rejected
because it lets the I side starve the D side or the reverse, and
nothing in the configuration would say which was intended.

**11. Anything else this task had to settle**

```
  a) PACKAGE MEMBER NAMES CARRY THE NODE NAME. l1i_addr_t,
     L2SetIdxLsb, mem_line_base. This is not decoration, see
     Deferred Work finding 1: without it the system build is

  b) THE INTERNAL REQUEST BUNDLE IS UNIFORM. Every protocol
     difference lives in an adapter and the control never sees

  c) A CACHE'S DOWNSTREAM MASTER MUST BE TILELINK. A line fill and

  d) ONE PORT PER INTERFACE. An interface carrying several ports
```

## Deferred Work

Four findings, in the order of how much they matter.

### 1. verilog_style.md's import rule is not merely inconvenient under Verilator. At system scale it is WRONG.

The rule says:

```
  Import at file scope, before the module declaration. Do not place
  import statements inside the module header between the module
  name and the port list.
```

A file scope wildcard import puts the package's members into
**$unit**, and $unit is shared by every file of one compilation.
Four node packages each declaring `addr_t`, `line_addr` and `Ways`
therefore collide the moment the system is built. This is not a
warning. It was OBSERVED: l2_ctrl.sv picked up l1i's `line_addr`,
which takes two arguments where l2's takes three, and l1i's 32 bit
`word_t` where l2's is 256:

```
  %Error: ../l2/rtl/l2_ctrl.sv:311: Too many arguments in call to
          function 'line_addr'
  %Warning-WIDTHEXPAND: ../l2/rtl/l2.sv:231: Output port connection
          'req_wdata' expects 256 bits ... generates 32 bits
```

Each node linted CLEAN on its own. The collision only appears when
more than one node is compiled together, which is the system build.
A project that only ever linted per node would ship this.

The module header form that verilog_style explicitly rejects,
`module foo import l2_pkg::*; (`, scopes the import to the module
and makes the problem impossible. That is what the form is FOR.

The emitter's answer was to keep the style rule and make the names
unique instead: every member of a node package carries the node
name, `l1i_addr_t`, `L2SetIdxLsb`, `mem_line_base`. It works, every
build is clean, and the emitted RTL is noisier for it.

**This is a ruling for you, not for the emitter.** Three options:

```
  a) keep the rule, keep the prefixing. Works today. Every hand
     written module in this project will have the same collision
     and no rule warns its author.
  b) allow the module header form for a wildcard import. One line
     in verilog_style. The prefixing then comes out and the RTL
     reads better.
  c) forbid wildcard imports, fully qualify at every use. Safe,
     verbose, and makes the placement rule moot.
```

Whatever is chosen, verilog_style.md should say WHY, because the
current text reads as a formatting preference and the thing behind
it is a correctness trap. planning/ is read only and nothing was
written there.

### 2. Arbitration is on the wrong scope for the contention this design actually has.

D-27 corrected arbitration from the link to the INTERFACE, on the
argument that an interface is the smallest scope that aggregates
every port contending for one link. The argument is right.

**Every interface in pacino carries exactly one port.** So no
interface has anything to arbitrate, and the field is inert on all
eleven of them.

What actually contends is l2's `up_i` against l2's `up_d` for the
banks behind them, and l2's two banks for the single downstream
link. Neither is an interface-scope contention and no field in any
schema describes either. The emitter chose round robin and says so
in the emitted file's header, which is the best it can do.

This is Q-08 with a concrete case attached. Q-08 says nothing
consumes arbitration and it becomes live when the emitter needs to
size an arbiter. The emitter has now needed two arbiters and
neither is the one the field describes. The likely shape of an
answer is that arbitration belongs on the NODE after all, for
exactly the reason D-27 rejected: what contends is the arrays
behind the interfaces. D-27 dismissed that as array port
scheduling rather than arbitration with a policy. In a banked cache
with two upstream interfaces it is both.

### 3. A testbench that drives or samples on the design's own clock edge races it, and the failure looks like a broken design.

Worth recording because it cost real time and the symptom pointed
the wrong way.

The first testbenches drove and sampled on the posedge, which is
the obvious thing to write. Every cache reported "no response" and
timed out. A cycle by cycle trace showed the DESIGN WAS CORRECT:
the request was accepted, the fill completed, and the response
pulsed exactly where it should. What was wrong was that the
testbench task, resuming after `@(posedge clk)`, saw POST edge
values, so a one cycle response valid was already gone by the time
it looked, and a request driven at the edge was taken in the same
instant it was presented.

Every driver, every wait and the reset release now use the negedge.
The design is posedge clocked, so at the negedge the cycle's values
have settled and are unambiguous. That convention is stated in the
emitted task set where a reader will find it.

The general point: **lint and elaboration cannot see this class of
defect, and a testbench that races the design fails in a way that
accuses the design.** It is worth an ANTIPATTERNS.md entry, which
TD-07 has been waiting for candidates for.

### 4. Three RTL defects that lint could not see, all found by the tests.

R-8c did not require simulation to pass. Taking it from "runs and
reports" to "passes" found three real bugs, and this is the
argument for the tests being worth the effort:

```
  a) THE L2's TL SLAVE ANSWERED A MULTI BEAT REQUEST WITH ONE
     BEAT. An L1 asks for a whole 64 byte line in one A beat and
     expects two D beats back; the L2's word is 32 bytes. The
     adapter ignored a_size and answered once. DEADLOCK, not a
     wrong answer, because the two ends disagreed about how many
     beats were owed. Every node linted clean and every unit test
     passed. Only the SYSTEM testbench could see it, because only
     there does a real L1 talk to a real L2.

  b) A FILL THAT ANSWERED A WRITE MISS ORed the written word into
     the fetched line instead of replacing it, so the read after
     it saw neither value. Invisible to l1d's tests by luck: l1d's
     tag lsb is 12, so the earlier test had already resident the
     address the write test used, and the write HIT. l2's tag lsb
     is 16, it missed, and the bug showed.

  c) THE FILL MERGE THEN RAN ON READS TOO, because the write
     strobe register still held the previous request's mask. A
     read installed a corrupted line. Found immediately by the
     test that had just been fixed.

  d) TRUE LRU's OBVIOUS RESET makes the highest numbered way the
     first victim, where tree PLRU's makes way 0. Not a bug, a
     divergence, and it would have made a cold cache fill
     differently depending on which policy was named. See R-9
     item 5.
```

None of these is a lint defect and none would have been found by
elaboration. The lint bar is necessary and it is not sufficient.

### Smaller items

- **bank_interleave_granularity word is derived, unresolved, and
  untested.** The path is live and reported: the select is inside
